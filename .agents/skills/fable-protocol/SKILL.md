# Fable Protocol

Use `AGENTS.md` for repository policy and `CLAUDE.md` section 5 for verification.
Keep this reasoning pass short; do not make another onboarding stack.

1. Establish the requested outcome, acceptance criterion and trust boundary.
2. Test the premise against the affected code/config/callers. Treat memory,
   old audits, issues and agent summaries as investigation leads.
3. State observations, inference and uncertainty separately. Verify mutable
   remote state or product facts when the conclusion depends on them.
4. Choose the smallest coherent change with a demonstrated benefit. Consider
   security, performance, maintainability and operator value at this scope.
5. Identify a check that could disprove the claim, execute it, and inspect the
   final diff. Reset diagnosis after three distinct failed hypotheses.
6. Report what was edited, tested, committed or published and any evidence gap.

Preserve I1–I6 and protected state. Plans, models and skill invocation grant no
runtime capability or publication permission. Use existing authorization;
do not ask again for ordinary reversible work within the requested scope.

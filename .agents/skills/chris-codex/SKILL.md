# Engineering Continuity

Use this public copy for requested continuity, not mandatory onboarding for
every edit. Read `AGENTS.md` and the current task's source. It transfers working
discipline, not capabilities, access or authorization.

1. Establish assessment, implementation or release scope. A clear fix request
   authorizes necessary scoped edits and verification; do not stop at a plan.
2. Preserve existing changes and task branches. Work in an isolated branch when
   needed; record actual base/head and refresh mutable remote state.
3. State the failure/desired behavior, smallest hypothesis and a check that
   could disprove it. Trace config, callers, alternate/retry and execution paths.
4. Preserve protected files, operator veto and application capability gates.
   Plans/model output cannot authorize execution or change policy.
5. Execute meaningful acceptance checks, inspect skips/mocks and report actual
   results. Use the active project's local/CI policy rather than importing a
   full-suite requirement from another repository.
6. Distinguish edits, local tests, commits, pushes, merged code and live operation.
   After three distinct failed hypotheses reset diagnosis and identify the next
   discriminating experiment; continue independent authorized work.

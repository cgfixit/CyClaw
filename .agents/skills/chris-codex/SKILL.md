# Engineering Continuity

Read the project's current instructions and owning source. Establish assessment, implementation or release scope and preserve existing work. Record the actual base and candidate. Name the expected behavior and a check that could disprove it, then trace config, callers, retries and side effects.

Run scoped acceptance and distinguish edits, tests, publication and deployment. After three distinct failed hypotheses, revisit the premise and choose a discriminating experiment. Keep independent authorized work moving.

Consult only the relevant reference:

- [CyClaw contracts](references/cyclaw-contracts.md) for product boundaries.
- [Verification](references/verification-playbooks.md) for evidence gaps.
- [Handoffs](references/task-and-handoff-contracts.md) for transfers and multi-PR work.
- [Other repositories](references/engineering-context.md) for portable guidance.
- [Maintenance](references/sources-and-maintenance.md) for this public skill.

Use trusted host metadata for model identity. The preference for non-Astra or unknown models is advisory. Explicit requests work on any model. Keep private history and personal-copy maintenance outside this workflow.
